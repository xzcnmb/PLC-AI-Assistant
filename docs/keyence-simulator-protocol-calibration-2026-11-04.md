# KEYENCE KV 模拟器协议校准记录 (2026-11-04)

本机实测: KV STUDIO 12G 12.42.0.0 中文版 + KV-X520(qa2 空工程)内置模拟器。
模拟器进程: `ACCommServer2.exe` + `KvEmuX5H3HMotion`(KV-X5H3H 仿真内核),PLC 状态 RUN。
监听端口: `127.0.0.1:8500`(SystemExtPortNo, ACL 二进制)与 `127.0.0.1:8501`(HostLinkPortNo, ASCII 上位链路),同属 ACCommServer2 (PID 13660)。

## 8501 — 上位链路 ASCII 协议: 校准通过 ✅

直接 `TcpClient` 连 `127.0.0.1:8501`,发送以 `\r`(CR) 结尾的文本命令,读回文本应答。

| 命令 | 应答 | 结论 |
|---|---|---|
| `RD DM100\r` | `00000` | 读单字, 5 位十进制 |
| `WR DM100 1234\r` | `OK` | 写单字成功 |
| `RD DM100\r` | `01234` | 写后读回一致 |
| `RDS DM100 3\r` | `01234 00000 00000` | 连续读, 空格分隔 |
| `WR DM100 -567\r` | `OK` | 负数写入接受 |

与基恩士《上位链路通信篇》(RMT.pdf) 公开的 RD/WR/RDS 指令集完全一致。
`WR` 应答是 `OK`(非数值),与部分第三方文档所述一致。

## 8500 — ACL 二进制协议: 直连探测无响应 ⚠️

按项目 `KeyenceAclTcpAdapter` 帧格式(`10 字节大端头 + 校验和`)逐一发送:

| 命令体 | 结果 |
|---|---|
| `03` (类型查询) | 无响应 (timeout) |
| `13 00 64 00 01` (DM100 读) | 无响应 |
| `13 00 00 00 01` (DM0 读) | 无响应 |
| `B2 00 00 00` (机型列表) | 无响应 |
| `05` (连接) / `02` (读会话) / `2D 04` (用户认证) | 无响应 |

同时 8500 端口发送 ASCII `RD DM100\r` 也无响应 —— 8500 不是 ASCII 通道。

**结论与下一步**: 8500 的 ACL 二进制在"模拟器已 RUN、TCP 直连、不加前置握手"条件下,
对以上候选帧均不返回。不排除需要 ① 模拟器侧先完成某种会话初始化/认证握手, ② 帧头路由/站号字段
(HDR[6..7]) 非零, ③ 命令体需要前缀长度/类型字段。这些需后续对 KVComm.dll / LDKCOM.dll 做调用级
逆向或用协议抓包(Wireshark 抓 KV STUDIO 自身连接 8500 的流量)来校准。
在未校准前, `KeyenceAclTcpAdapter` 对真实模拟器的定位保持 `experimental`, 8501 ASCII 通道可作为
可靠的本地实测替代(simulator loopback 已通)。

## 补充探测 (2026-11-04 下午)

- 8500 上对头域 [6..7] 路由/站号字段逐一尝试 0x0000/0x0001/0x0002/0x0003/0x0080/0x00FF/0x0100/0xFFFF,
  配合 0x03、0x13 命令体, 全部无响应 → 确认与路由字节无关, 8500 需要的是会话级初始化/认证握手,
  当前直连裸帧无法触发应答。
- KV STUDIO 与 ACCommServer2 之间无已建立的 TCP 连接(8500/8501 仅 LISTENING),
  说明 KV STUDIO↔模拟器的日常通信不走 8500 裸 TCP, 8500 是供外部上位机(带正确握手)使用的通道。
- 因此任务 D(程序传输帧上机验证)在无会话级逆向/抓包条件下, 只能做到:
  - 8501 ASCII 通道端到端验证(读/写/连续读, 已通过);
  - 8500 ACL 程序传输帧(0x38/0x39/0x46 族)保持 [U] 未校准状态, 待会话级握手逆向后再上。
  这是诚实边界, 不越过。下一步建议: 用 Wireshark/pktmon(管理员)在 KV STUDIO 执行"PLC 传输"时抓
  127.0.0.1:8500 流量, 比对 KVComm.dll 调用时序以恢复握手。
